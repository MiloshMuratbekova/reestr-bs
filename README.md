# Реестр БС

Интеллектуальная веб-система выявления и анализа бенефициарных собственников
юридических лиц. Агентство по финансовому мониторингу Республики Казахстан.

Система работает в закрытом контуре, без доступа в интернет.

---

│ритмов     │ │цы результатов │ │                   │

Отдельный веб-сервер не нужен: приложение отдаёт и API, и интерфейс на порту
8020. Документация API работает без интернета — Swagger UI лежит локально.

Ключевое решение: **итоговая таблица реестра не хранится**. Она рассчитывается
запросом к ClickHouse при каждом обращении поверх таблиц результатов алгоритмов —
как того требует ТЗ. Пересчитываются только сами таблицы алгоритмов
(`POST /api/recalculate`).

### Порядок расчёта

Часть алгоритмов читает результаты других, поэтому пересчёт идёт в порядке
топологической сортировки:

* **БС-11** зависит от БС-1 и БС-3 (исключает уже найденных БС);
* **БС-13** зависит от БС-1 и БС-3 (БС покупателя);
* **БС-17** зависит от БС-1, БС-2, БС-22, БС-3, БС-4 (цепочка установления
  конечного ФЛ-бенефициара иностранной компании).

Если базовый алгоритм упал, зависимые пропускаются — иначе они посчитались бы
по устаревшим данным. В ответе `/api/recalculate` такие помечены статусом
`skipped`.

### Итоговая таблица

Из каждого алгоритма берутся `taxpayer_iin_bin`, `benefeciary_iin_bin`, `status`,
`algorithm_code`, `priority`, `_actual_date`, `dop_info`. Дальше:

* наименование компании — `AFM_2_1_TEST.AFM_2_1_9`;
* имя бенефициара — `AFM_2_1_TEST.AFM_2_1_10`; если не найдено, то для **БС-7**
  и **БС-17** берётся часть `dop_info` до первой запятой, для остальных —
  весь `dop_info`;
* категория — `AFM_2_1.AFM_2_1_8` (см. п. 4.2 в `docs/sql-fixes.md`);
* документ — `AFM_2_1.AFM_2_1_59`, строка вида
  `номер документа: …, номер серии: …`;
* доля участия — `AFM_6_TEST.AFM_6_1_5_1`.

Баллы: `ball1` — сумма `priority` по компании, `ball2` — по паре
компания-бенефициар, `ball3 = round(ball2 / ball1 * 100, 2)`.
Исключаются строки, где пуст и ИИН, и имя бенефициара.

## API

Базовый префикс `/api`. Все методы, кроме `/auth/login` и `/health`,
требуют заголовок `Authorization: Bearer <token>`.

| Метод | Путь | Роль | Назначение |
|---|---|---|---|
| POST | `/auth/login` | — | Вход, выдача JWT |
| GET | `/auth/me` | любая | Текущий пользователь |
| GET | `/auth/users` | administrator | Список пользователей |
| POST | `/auth/users` | administrator | Создать пользователя |
| GET | `/search` | любая | Поиск компаний с показателями реестра |
| GET | `/company/{bin}` | любая | Карточка компании |
| POST | `/company/{bin}/explain` | любая | Объяснение от Qwen |
| POST | `/chat` | любая | Вопрос аналитика по компании |
| GET | `/stats` | любая | Общая статистика реестра |
| GET | `/algorithms` | administrator | Список алгоритмов |
| POST | `/algorithms` | administrator | Создать алгоритм |
| GET | `/algorithms/{code}` | administrator | Алгоритм по коду |
| PUT | `/algorithms/{code}` | administrator | Обновить SQL, сохранить историю, выполнить |
| GET | `/algorithms/{code}/history` | administrator | История версий SQL |
| POST | `/algorithms/{code}/rollback/{id}` | administrator | Откат на версию из истории |
| POST | `/algorithms/{code}/run` | administrator | Запустить алгоритм |
| POST | `/algorithms/{code}/ai-update` | administrator | Предложение нового SQL от Qwen |
| POST | `/recalculate` | administrator | Пересчитать все активные алгоритмы |
| GET | `/settings` | administrator | Настройки подключений и лимитов |
| POST | `/settings` | administrator | Сохранить настройки (белый список ключей) |
| POST | `/ch/test` | administrator | Проверка подключения к ClickHouse |
| POST | `/db/test` | administrator | Проверка подключения к PostgreSQL |
| POST | `/llm/test` | administrator | Проверка модели коротким запросом |

Всё, что не начинается с `/api`, отдаётся интерфейсом: конкретный файл сборки
либо `index.html` для маршрутов SPA вида `/company/123456789012`.

## Настройки через интерфейс

Раздел «Настройки» (только администратор) позволяет менять адреса ClickHouse
и PostgreSQL, сервер и модель ИИ, а также лимиты — **без правки файлов
и перезапуска контейнера**. Соединения пересоздаются сразу после сохранения.

Три слоя и приоритет:

1. умолчания в коде, читающие переменные окружения (`.env`, `docker-compose.yml`);
2. файл `data/settings.json` в томе `reestr-bs-data`;
3. при загрузке берутся умолчания, **поверх накладывается файл**.

> **Сохранённое через интерфейс сильнее `docker-compose.yml` и `.env`.**
> Если адрес поменяли в compose, контейнер перезапустили, а система ходит
> по старому адресу — причина в сохранённом файле, а не в окружении.
> Источник каждого значения виден в ответе `GET /api/settings` (поле `source`)
> и в самом интерфейсе.

Защита:

* редактируются **только ключи из белого списка** `EDITABLE_KEYS`, остальное
  из запроса отбрасывается;
* все числовые лимиты **зажимаются на сервере** — ограничение в поле ввода
  обходится прямым запросом к API;
* пароли **не возвращаются** наружу: отдаётся признак «задан / не задан»,
  пустое поле при сохранении не затирает существующий пароль;
* пароли не попадают в журнал; `data/` внесён в `.gitignore` и `.dockerignore`;
* проверки подключений **не выбрасывают исключений** — возвращают `ok` и
  понятную строку, по которой видно: не тот адрес, не пускает по паролю
  или недоступна сеть.

Приложение работает в несколько воркеров uvicorn — это отдельные процессы.
Каждый следит за временем изменения файла настроек и перечитывает его,
иначе сохранённое применялось бы через раз.

## Роли

* **administrator** — полный доступ, включая управление алгоритмами, пересчёт
  и настройки подключений.
* **user** — просмотр данных, объяснения ИИ и чат.

Первичный администратор создаётся при первом старте из переменных
`FIRST_SUPERUSER` и `FIRST_SUPERUSER_PASSWORD`.

## Бизнес-правила интерфейса

* Компании с типом собственности, содержащим «Государственная», помечаются
  флагом **Гос**; список БС для них не выводится, вместо него — предупреждение.
* Сортировка БС: сначала регистрационные (`priority = 0`), затем предполагаемые
  по убыванию `ball3`.
* Цвет карточки бенефициара по вероятности: выше 70 % — красный,
  40–70 % — жёлтый, ниже 40 % — зелёный.
* Пустые значения выводятся прочерком «—».
* Ошибки ClickHouse и Qwen показываются понятным сообщением на русском языке,
  без технических деталей.

## Хранение SQL алгоритмов

SQL лежит в PostgreSQL (`bs_registry.bs_algorithms`), а выполняется в ClickHouse.
При первом старте таблица заполняется из файлов `backend/app/algorithms/sql/`.
Дальше приоритет у базы: правки администратора через интерфейс не затираются
при перезапуске.

При изменении SQL прежняя версия попадает в `bs_algorithm_history` вместе
с причиной и автором правки, номер версии увеличивается. Есть откат на любую
сохранённую версию.

Скрипт алгоритма может содержать несколько операторов через `;` — бэкенд
разбивает его с учётом строковых литералов и комментариев и выполняет
последовательно. Это нужно, например, БС-13: пять промежуточных таблиц,
финальный `CREATE TABLE` и удаление временных таблиц.

## Развёртывание

Сервер `10.10.31.35`, Linux amd64, интернета нет. Два способа.

### Docker — основной

Подробно: [docs/deploy-docker.md](docs/deploy-docker.md).

На машине с интернетом собирается комплект:

```bash
./scripts/build-release.sh 1.0.0        # или scripts\build-release.ps1 на Windows
```

Получается `reestr-bs-1.0.0.tar` (188 МБ) с образами приложения
и PostgreSQL. На сервере:

```bash
mkdir -p ~/reestr-bs && cd ~/reestr-bs
tar xf ~/reestr-bs-1.0.0.tar
docker load -i images.tar
cp .env.example .env      # заполнить POSTGRES_PASSWORD, SECRET_KEY, пароль администратора
docker compose up -d
```

PostgreSQL поднимается контейнером, Python и Node.js на сервере не нужны,
версия Python зафиксирована образом.

### Без Docker

Подробно: [docs/deploy.md](docs/deploy.md).

```bash
sudo -u postgres psql -f backend/sql/01_create_database.sql
cd backend
python3 -m venv .venv && source .venv/bin/activate
pip install --no-index --find-links=./wheels -r requirements.txt
cp .env.example .env
uvicorn app.main:app --host 0.0.0.0 --port 8020
```

Заранее подготовлено: `backend/wheels/` — 39 пакетов под Linux amd64
(**Python 3.11**), `frontend/dist/` — собранный интерфейс,
`backend/app/static/swagger/` — локальный Swagger UI.

### После запуска

Открыть `http://10.10.31.35:8020`, войти администратором → «Алгоритмы» →
запустить по одному, затем «Пересчитать всё».
Расчёт БС-13 по ЭСФ (~485 млн строк) занимает часы.
